## 🔴 TOP COMPLETION ITEM — Email deliverability is silently broken for some founders

**Root cause (confirmed from Postfix `mail.log` + DNS):** Godseye sends email from `noreply@godseye.digitalhustlerx.com` via the local Postfix relay. Gmail now rejects a large share of those with:

```
550-5.7.26 Your email has been blocked because the sender is unauthenticated.
       DKIM = did not pass
       SPF [godseye.digitalhustlerx.com] with ip: [2a02:c207:2319:3150::1] = did not pass
```

**Why it's intermittent:** 
- The box has two outbound IPs — IPv4 `62.84.186.1` (authorized by SPF `+a`) and IPv6 `2a02:c207:2319:3150::1`.
- Postfix `inet_protocols = all` sends via whichever it picks. IPv4 → SPF pass → delivered. IPv6 → **SPF fail** → rejected.
- **DKIM is not configured at all** (`DKIM = did not pass` on every send), so IPv6 sends have no second authentication channel.

**Demonstrated impact on real signups (from `/var/log/mail.log`):**
- ❌ `getviralcity@gmail.com` — real waitlist signup w/ founder code — **rejected 5.7.26**
- ❌ `marvzplug@gmail.com` — real signup w/ founder code `FDR-C9BB29C8` — **rejected 5.7.26**
- ✅ `officialvendet@gmail.com`, `popup.test.user@gmail.com` — delivered (happened to go via IPv4)

Because `drip_jobs` marks the job `sent` when Postfix *accepts* it, the DB shows **no failure** — the founder cannot see that these founder-welcome / drip emails never arrived. This is the #1 pre-launch conversion lever and it is dropping real leads silently.

### Recommended fixes (apply after signoff — all require system/DNS authority, which this cron should not change unilaterally)

1. **Immediate, zero-DNS-DNS:** Force Postfix outbound onto IPv4 only →
   `postconf inet_protocols=ipv4` (then `postfix reload`). Stops all IPv6 SPF-fail sends tonight.
2. **Add DKIM** (OpenDKIM) + publish `_domainkey` TXT on `godseye.digitalhustlerx.com`. Gmail then passes on DKIM even if SPF path flips.
3. **Harden SPF:** add `+ip4:62.84.186.1` (already implied by `+a` today) and ideally `+ip6:` for the real v6 — or leave IPv4-only and go with fix #1.
4. **Repair bounce loop:** Bounces to `noreply@godseye.digitalhustlerx.com` currently "loop back to myself" and are dropped. Align sender with a monitored mailbox so failures are visible.
5. **Surface real failures:** consider checking `smtp` (not just Postfix-accept) outcome in the drip worker, so a rejecting provider marks the job `failed` instead of `sent`.
