**Bottom line:** A user who signs up via the live CTAs (`app.digitalhustlerx.com/signup` → OpenSaaS "GodsEye Cloud Console") is created in **OpenSaaS's PostgreSQL**, on **port 3101** — a **separate application** from the Godseye backend on **port 3000** (SQLite). The Godseye `/api/auth/register` + `/api/polar-webhook` path — the ONLY code that grants a **license, 50 starting credits, founder-spot, and Polar checkout** — is **never triggered** by an OpenSaaS signup. There is **no bridge/webhook** between the two.

Verified evidence (reads, not assumptions):

|---|---|
| Godseye backend binds | 127.0.0.1:3000 (SQLite `data/godseye.db`) — `users` table = **2 rows** (`officialvendet`, `prod.acct.verify`) |
| OpenSaaS app binds | Wasp/Prisma on **3101**, postgres, own `schema.prisma` `model User` with its own payment fields (LemonSqueezy) |
| nginx `app.digitalhustlerx.com` | `root .../open-saas/template/app/.wasp/out/web-app/build`; `/auth/ /operations /queries /actions /rpc /api/` → `proxy_pass http://127.0.0.1:3101` |
| Any bridge in `server.ts` | **None.** No `opensaas`/`wasp`/`user.created`/`account.created` webhook. `grep -rn opensaas server.ts` = nothing. |
| OpenSaaS HANDOFF.md | *"PORT 3000 IS GODSEYE — DO NOT TOUCH"*; OpenSaaS is intended as **its own project** (payments placeholders: Stripe `sk_test_...placeholder`; `PAYMENTS_CREDITS_10_PLAN_ID` = placeholder) |
| OpenSaaS QA-REPORT.md | *"Payments — Stripe/LemonSqueezy/Polar are placeholders; 'Buy More Credits' will fail until a payment processor is configured."* |
| OpenSaaS watcher (`godseye-watcher.sh`) | Health-checks the **Godseye** webhook `api.godseyes.../payments-webhook` — the hook that lives on :3000, not :3101 |

**Consequence:** The live "Get 50 free credits" + signup flow delivers a user into a console whose **credits are placeholders and whose payment is unconfigured**, while the functioning Godseye grant/checkout path sits orphaned. Only ~2 real Godseye users exist despite the funnel presumably capturing signups.
